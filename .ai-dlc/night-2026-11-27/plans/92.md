## INTENT

Add an app-local transient volume indicator ("toaster", ReTune capture-22
parity per `docs/retune-capture/22-volume-toaster/notes.md`): a floating
level bar in the center band (y≈900–1500) shown on a server-volume step,
auto-hiding ~1–2.5 s without interaction, exposing no a11y node — on every
screen **except** NowPlaying, where the existing 0–100 slider remains the
indicator and must keep following each rocker step. The rocker→server
mechanism (#84/R-06/D20), the NP slider, and `rocker.step` semantics are
explicitly unchanged (issue Non-goals).

## APPROACH

Why this shape: the bar must render **above opaque pushed routes**, which is
only possible from a layer mounted above the app `Navigator` — `MaterialApp`'s
`builder` is the sanctioned slot (it wraps the Navigator; its context sits
above it, so `ModalRoute.of` is null there and route awareness must come from
an observer). ReTune's Toast is a11y-invisible and non-interactive →
`ExcludeSemantics` + `IgnorePointer`. The trigger lives on `PlayerController`
because `stepVolume` is the **only** rocker entry point (grep above) and its
`_action` gate (`api != null && isConnected`, player_controller.dart:168-169)
is exactly the "was a request issued" condition AC-4 names; a volume *diff*
would false-trigger (WS `volume` events from the shared server and the NP
slider both change `volume` — the signal must be a dedicated step event).

1. **`lib/src/ui/volume_toaster.dart` (new)** —
   - `class VolumeToasterLayer extends StatefulWidget`: builds
     `Stack([widget.child, if (visible) bar])`. Reads providers with the
     in-repo nullable idiom (mini_player.dart:31-38:
     `Provider.of<PlayerController?>(context, listen: true)` → null ⇒ renders
     just `child`; keeps the existing `OwntoneRemoteApp` test harnesses that
     register no player provider working). Watches `PlayerController`; when
     `volumeStepSeq` changes since last seen **and** the route observer says a
     pushed route is on top (depth ≥ 2), show the bar at `volumeStepLevel`.
   - Bar: `Align(alignment: Alignment.center)` (device center ≈ y1200 of
     2400 — inside the capture-22 band 900–1500), a rounded Material pill
     (theme `colorScheme.surface*` + elevation) containing a volume icon,
     `LinearProgressIndicator(value: level / 100)` and `Text('$level')` —
     wrapped in `ExcludeSemantics` (AC-6) and `IgnorePointer` (AC-5
     non-blocking). Rendered by this app's own widget layer (no dependency,
     no ReTune assets — Non-goals).
   - Auto-hide: one `Timer` (state field) of **1500 ms** (inside the ~1–2.5 s
     ReTune window); a new step while visible **resets the timer and updates
     the level in place** (AC-3 — single bar, never a stack). `dispose()`
     cancels the timer (flutter_test pending-timer invariant — unit-3
     discovery_scan_test lesson).
   - `class VolumeToasterRouteObserver extends RouteObserver<ModalRoute<void>>`
     with `int get depth` maintained `didPush +1 / didPop −1 / didReplace 0`.
     Suppression rule: depth ≤ 1 ⇒ root route on top ⇒ (connected/offline)
     that is NowPlaying (root_screen.dart doc + R-21 drawer invariant) ⇒
     suppressed. Exported for `main.dart` + tests.
2. **`lib/main.dart` (edit, `OwntoneRemoteApp` only)** —
   `MaterialApp(navigatorObservers: [_toaster], builder: (context, child) =>
   VolumeToasterLayer(child: child!), ...)`. `main()` / providers /
   `_initAudio` untouched. The existing injectable `home` keeps working, and
   harnesses pumping `OwntoneRemoteApp` (settings/theme/drawer tests) get the
   layer for free (inert without a player provider).
3. **`lib/src/player/player_controller.dart` (edit)** — add `int
   volumeStepSeq` + `int? volumeStepLevel`; in `stepVolume(step)`: **only
   when `_conn.api != null && _conn.isConnected && _player != null`** (the
   same gate `_action` uses to decide "request issued"), set
   `volumeStepLevel = (_player!.volume + step).clamp(0, 100)` — the exact
   expression the optimistic `copyWith` applies (line 283), so bar and NP
   slider agree by construction — and bump `volumeStepSeq`, then delegate to
   `_action` unchanged (the optimistic notify that follows carries the
   signal; no extra notify, no signature change, `handleVolumeKey`'s key
   answer stays `true` as today). Offline / no-slice presses: no bump, no
   notify ⇒ layer never schedules a timer (AC-4/AC-7). Failure of the PUT
   does not early-hide the bar (it shows the level *requested*; rollback +
   snackbar stay as they are — A-5).
4. **`test/rocker_foreground_test.dart` (edit)** — new test asserting
   `player.volumeStepSeq` bumps exactly once per accepted press and **not at
   all** for declined ones (backgrounded, un-registered, bad direction).
5. **`test/volume_toaster_test.dart` (new)** — see `## TESTS`.
6. **`docs/SESSION-LOG.md`** — builder entry (AC-8).

Out of scope / untouched (issue Non-goals): `mirror_handler.dart`,
`now_playing_screen.dart`, `android/`, `rocker.step` setting, notification,
`pubspec.yaml` (no new deps), `main()` body, session `fixed` publication.

## RISKS

- **A-1 (assumption):** NP suppression == "root route on top" (observer depth
  ≤ 1). Sound only under the documented nav invariant (root_screen.dart:
  every screen is pushed on top of the NP root; drawer destinations collapse
  to `[root, target]`). If that ever changes the gate misfires — T10 pins the
  invariant from the UI side.
- **A-2 (fallback):** the depth counter leans on `RouteObserver` delivering
  `didPop` for every pop of `Navigator.popUntil` (used by both nav helpers).
  T10 exercises exactly this (deep stack → `showDrawerDestination` →
  `showNowPlaying`). If it ever diverges, the two centralised nav helpers
  (`showNowPlaying`, `showDrawerDestination`) get an explicit re-sync call —
  shape decision recorded here so the builder need not invent one.
- **A-3 (assumption):** auto-hide = 1500 ms fixed (inside the machine-verified
  ReTune ~1–2.5 s band); no settings toggle (issue Non-goal).
- **A-4 (assumption):** trigger = dedicated `stepVolume` seq/level bump gated
  by `_action`'s request condition (`api != null && isConnected && _player !=
  null`). A connected-but-no-first-slice press issues its PUT but shows no
  bar (no level exists) — minimal interpretation, visually matches the
  pre-init disabled-controls state; recorded per role "minimal
  interpretation wins".
- **A-5 (assumption):** a failed PUT does not early-hide the bar (AC-4 says
  "level actually requested"; rollback snackbar unchanged; ≤1.5 s anyway).
- **A-6 (assumption):** "no a11y node" = content wrapped in `ExcludeSemantics`
  (parity, not an a11y fix — issue Non-goal). T6's negative assertion is
  route-scoped (Queue carries no other volume text), so it cannot false-green
  against an unrelated label.
- **A-7 (assumption):** drawer open over NP = suppressed (not a route; NP is
  what's on screen); phase screens (idle/connecting/error) are non-NP so the
  layer mounts but stays inert (no connection ⇒ no request ⇒ no signal —
  AC-4). No special-casing.
- **VERIFY-LIVE-1 (builder, before the device pass):** the step PUT is
  accepted while paused on the shared server (204 / relative GET delta),
  then baseline 46 restored + verified. `docs/API.md`:70 documents it and
  dv-004/R-14 device-evidence exists, but the server is shared — re-confirm
  live, don't trust.
- **VERIFY-LIVE-2 (builder, throughout):** shared-server churn — the other
  session may move `volume`/`state` at any moment. Keep all assertions
  relative, re-check pause immediately before each step-PUT, and the final
  invariant check is "we never issued a play-class call" + stable pause
  (run-config invariant 1), not a single snapshot.
- **Harness risk:** flutter_test pending-timer invariant — the layer's timer
  must be cancelled in `dispose()` (unit-3 `discovery_scan_test` precedent);
  T2/T3/T9 shape the pumps accordingly.
- **Harness risk:** the semantics walk needs an active `SemanticsHandle`; if
  `rootSemanticsNode` is null the test must `ensureSemantics()` first
  (mini_player_test does exactly this).
- **Regression risk:** `OwntoneRemoteApp` gains `builder`/`navigatorObservers`
  — the harnesses that pump it without player providers (settings/theme/
  drawer-deferred tests) rely on the layer's nullable-provider idiom
  (mini_player.dart precedent); those suites re-run in the gates.
