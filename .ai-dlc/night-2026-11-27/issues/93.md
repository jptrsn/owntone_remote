## Title

Cold boot while server unreachable stays in error phase forever — no
auto-retry (only 'offline' has the probe timer)

## Body (verbatim)

## What
Launch the app while the server is unreachable (e.g. wifi off / server down) → `connectTo` fails → `ConnectionPhase.error` → the error screen with **Retry**. When the server comes back, nothing re-drives `connectTo`: the `offline` `Timer.periodic` only exists in the offline phase, and there is no connectivity listener. The app waits on the error screen until the user taps Retry (or the process is killed).

Observed 2026-11-26 (host session, Pixel 6): cold boot with wifi off (media session already up from `_initAudio`), wifi back on → 60 s of `active=false` / error screen; `conn.retry()` (the button's call) immediately recovered: `error → connecting → connected`, session `active=true`.

## Why it matters
Same user-visible class as #81 (session/connection should self-heal without user action): a rebooted phone + restarted server = dead remote until someone taps.

## Candidate fix
Start the same probe/retry timer in `error` phase (a failed `connectTo` with a network-y Dio error is indistinguishable from offline for recovery purposes), and/or a connectivity listener that calls `retry()` on network-available when phase is `error`.

## Where
`lib/src/connection/connection_controller.dart` (error paths ~239/243 vs `_offlineProbe` ~373), `lib/main.dart`.

Context: found while host-verifying PR #88 (evidence: pull/88#issuecomment-7207241774); explicitly **not** a #88 regression.
