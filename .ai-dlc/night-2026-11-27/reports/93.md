## ASSUMPTIONS

1. **Plan deviation (guarded continuations).** Plan R-1 parked the missing
   `_generation` guard on `connectTo`'s continuations as out-of-scope,
   arguing "the error timer only fires when no attempt is in flight" — true
   for tick-vs-tick, but `disconnect()` (and a newer `connectTo`) while a
   tick-attempt is in flight leaves the stale catch to land `idle → error`
   **and re-arm the timer**, making the plan's own T6 ("explicit disconnect
   is final") non-deterministic (~attempt-window per cycle). Fixed with the
   file's established `_probeServer` pattern (capture `_generation` after
   the prologue teardown; discard continuations on mismatch), which
   incidentally closes the parked R-1 class. Necessity shown by mutation,
   not    argument (see GATES). **Review round 1 correction:** the earlier claim
   "reverting the guard re-breaks T6" is wrong — T6 as written disconnects
   only while the timer has no attempt in flight (fake-zone ticks settle
   instantly), so it never enters the race window; deleting the three
   `connectTo` guards leaves T1–T8 and the full 670 green. The race exists
   only when `disconnect()` lands mid-attempt (`_ConnectingScreen` Cancel,
   root_screen.dart:103, reachable during the 5–15 s connecting window) and
   is pinned by the committed test **T9** in
   `connection_error_auto_retry_test.dart` (Completer-held attempt →
   `disconnect()` → release → `phase == idle`, `errorMessage` null, request
   count frozen; deleting the guards reddens T9 deterministically —
   `Expected: idle / Actual: error`, reproducing the reviewer harness).
2. **Plan prefs recipe wrong (evidence-based).** Plan § DEVICE seeds
   `shared_prefs/dev.educoder.owntone_remote.preferences.xml` with raw keys
   `server.host`/`server.port` — `shared_preferences_android` 2.4.10 reads
   `FlutterSharedPreferences.xml` with `flutter.`-prefixed keys
   (`SharedPreferencesPlugin.kt:33 SHARED_PREFERENCES_NAME`). Observed:
   first seed ignored (app rendered the Connect/first-run screen); re-seed
   as `flutter.server.host`/`flutter.server.port` →
   `auto-connecting to 192.0.2.1:3689`.
3. **VERIFY-LIVE 2 fell back to airplane mode** (`cmd connectivity
   airplane-mode enable`) — `svc wifi disable` is framework-honoured but not
   isolating on this emulator image (eth0 stays up). This realises the
   plan's A-5 ("server unreachable ↔ reachable again") with the same
   observable shape as the issue's wifi-off/on observation.
4. **`pm grant` instead of dialog taps** for POST_NOTIFICATIONS +
   READ_PHONE_STATE (first-launch `GrantPermissionsActivity` was blocking
   `main()` before auto-connect; run-config hard rule prefers no taps).
5. **T1 post-pump settle.** A periodic tick firing milliseconds before the
   `pump(160)` return leaves the phase momentarily `connecting`; the strict
   "phase == error" check became a settle-wait (`down` still true ⇒ can only
   land in `error`). Assertion strength unchanged.
6. **Existing widget test adapted (only non-new test touched).**
   `discovery_scan_test.dart`'s DNS test now ends with `conn.disconnect()`
   before the body exits: the new recovery timer is a live periodic in the
   fake zone and `flutter_test`'s pending-timer invariant rejects the test
   otherwise (one-line change + comment; timer behaviour itself is pinned at
   ms scale in the new file; full suite green).
7. **No `analysis_options.yaml` churn** appeared in this run (nothing to
   commit there).
