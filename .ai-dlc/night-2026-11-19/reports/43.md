## SUMMARY

R-26 (numbering per orchestrator adjudication — issue proposed R-21, taken):
the app now offers **Light · Dark · Follow system**. `MaterialApp` gained
`darkTheme` (`ColorScheme.fromSeed` with the existing seed `0xFF7C5CBF`,
`brightness: dark`) and a `themeMode` bound to a new listenable
`ThemePreference` (`lib/src/settings/theme_preference.dart`) that mirrors
the persisted `theme.mode` key added to `SettingsStore` (untyped `prefs.get`
read — `getString` THROWS on a wrongly-typed legacy value; untyped read is
what makes "corrupt → System, never crash" true). The picker is a
`SegmentedButton<ThemeMode>` with `ValueKey('theme-mode-picker')` in
Settings, directly below the rocker-step row (labels Light/Dark/System),
applied on select without restart. The two `Colors.grey` placeholders in
`now_playing_screen.dart` became `colorScheme.onSurfaceVariant`.
`OwntoneRemoteApp` gained an injectable `home` so the theme contract is
widget-testable without every `RootScreen` provider; `docs/REQUIREMENTS.md`
gains R-26 with the issue's acceptance list. Tests: 5 new store cases +
6 new app-level cases (`test/theme_mode_test.dart`) + 2 new picker cases
(`test/settings_screen_test.dart`), all citing R-26, all network-free via
`SharedPreferences.setMockInitialValues`. Two harness lessons cost real
iterations and are encoded as test comments: `MaterialApp` wraps the
resolved theme in an `AnimatedTheme` (200 ms) so theme-state widget tests
must `pumpAndSettle`, and `TestPlatformDispatcher` needs
`binding.handlePlatformBrightnessChanged()` after setting the brightness
test value.
