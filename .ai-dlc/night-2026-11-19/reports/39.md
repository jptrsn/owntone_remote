## SUMMARY

R-17 (diff-list D-04, `docs/retune-capture/15-now-playing/notes.md`): the
now-playing overflow now carries **Go to Artist** → `ArtistAlbumsScreen` and
**Go to Album** → `AlbumTracksScreen` for the current track, ReTune's two np
context actions. `NowPlayingItem` (`player_state.dart`) gains `albumId` /
`albumArtistId` parsed from the queue item's `album_id` /
`album_artist_id`; `now_playing_screen.dart` builds the two browse targets
each frame from the cached `controller.nowPlaying` and renders a
`PopupMenuButton` (tooltip 'More') in the app bar pushing them via the
standard `Navigator`/`MaterialPageRoute` pattern the browse screens use.
An entry with no id behind it is not rendered, and the whole button is
absent with no track loaded; while offline the rows render but are inert
(`enabled: false` + an `onSelected` guard), matching the entry row's
disabled-while-offline pattern.

**Payload verification first (per the unit brief):** live read-only GETs
(2026-11-20) — `GET /api/player` → `pause`, `item_id 211696`;
`GET /api/queue?id=now_playing` and `GET /api/library/tracks/974` carry
`album_id: "2869814693581682457"` and `album_artist_id:
"883237247873166043"` as **strings and no plain `artist_id`**; and
`GET /api/library/artists/883237247873166043/albums` returns that artist's
albums — so `album_artist_id` is the id the artist-albums endpoint accepts,
and it is what the artist target is built from.

Tests: 4 new cases in `test/now_playing_screen_test.dart`, all citing R-17,
network-free via the existing fakes — loaded track: both entries present and
each tap pushes its route **found by widget type** (`find.byType(ArtistAlbumsScreen)`
/ `AlbumTracksScreen`) and renders the fake server's real albums/tracks,
back returns; stopped: entries absent; track without browse ids (defensive
branch): button absent; offline with cached track: rows present, all
`PopupMenuItem.enabled == false`. The fixture's new `albumId`/
`albumArtistId` fields default **null** (opt-in by the R-17 tests) so every
pre-existing test keeps its exact queue payload — a present `album_id`
flips the artwork fallback branch (`./artwork/album/<id>`), which would
otherwise change frozen artwork/viewport tests.

## ASSUMPTIONS

- **"absent/disabled" resolved to absent** (the frozen spec allowed either):
  with no track loaded (stopped) the overflow button and both entries are
  **not rendered**; per-entry they are also hidden when the id behind them
  is missing (defensive branch — the server sends both for file tracks).
  **Offline** with a cached track keeps the rows visible but **inert**
  (`enabled: false`), matching the entry row's disabled-while-offline
  pattern rather than hiding live navigation. All three states are pinned
  by widget tests.
- **Artist target id = `album_artist_id`**: queue items and library tracks
  carry no plain `artist_id` (curl-verified 2026-11-20, both payload sites),
  and `GET /api/library/artists/{album_artist_id}/albums` returns the right
  albums — so that is the id wired (recorded in the `NowPlayingItem` doc
  comment so a future reader does not "tidy" it to `artist_id`).
- Constructed browse models carry zero counts (`Artist.albumCount/…`,
  `Album.trackCount/lengthMs`) and a synthetic `library:album:<id>` uri —
  `ArtistAlbumsScreen` reads only `id`+`name`, `AlbumTracksScreen` only
  `id`+`name`, and the uri mirrors `Album.fromJson`'s fallback. Nothing in
  the pushed routes consumes the placeholders today.
- Fixture browse ids default **null** (opt-in) — keeping them defaulted-on
  would flip the frozen artwork-fallback/viewport tests' payloads (observed
  failure then green after opting in).
- Evidence channel: after 3 honest `flutter run` failures (tool-side,
  documented above) the accepted fallback (uiautomator + screencap + VM
  service) carried the pass; screencaps are on-disk-only (no model image
  input).
- Phone-call permission denied / notification permission allowed on first
  launch — local dialogs, irrelevant to the navigation claims; the
  notification channel is what the media FGS uses, no audio involved.
- Scratch files for the run went to the sandbox pre-approved temp dir
  (`/var/folders/…/T/opencode/owntone-night/`); literal `/tmp/owntone-night/`
  was blocked by the sandbox (`/tmp` resolves to `/private/tmp`, outside the
  allowed pattern). In-scope alternative per the standing instructions.
