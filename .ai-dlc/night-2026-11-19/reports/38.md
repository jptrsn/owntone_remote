## SUMMARY

Library home gains a **Songs** section (between Albums and Genres,
`Icons.music_note`) opening `TracksScreen` — a thin `PagedBrowseScreen`
wrapper mirroring `AlbumsScreen`: `PagedList(fetch: api.tracks, keyOf:
track.id)` + existing `TrackRow`s with `showArtist + showAlbum` (new) →
two-line rows `title` / `artist - album` (ReTune `12-songs` reference) +
the R-12 star control + the R-10 row-tap play (replace queue + start).
The #48 `groupKeyOf` flag is **enabled on Songs** as adjudicated — grouped
by the server's `title_sort` (the served order), reusing
`browseSectionKey` unchanged.

**Endpoint adjudication (spec correction, verified before building):**
the frozen spec's `GET /api/library/tracks` (paginated) **does not exist**
on this server. Source-checked the OwnTone 29.3 JSON-API route table
(`src/httpd_jsonapi.c` fetched from upstream): only
`/api/library/tracks/{id}` GET/PUT, the batch PUT, and
`/tracks/{id}/playlists` exist — no collection route; and **live**: 400
for every parameter combination tried (`query=`, `cc=`+id, DAAP-style
`query=(all)`, `expression=`…). The all-tracks list therefore rides the
proven search endpoint (same route `genreAlbums` already uses):
**`GET /api/search?type=tracks&query=&offset=&limit=`** — the server's
empty-query branch is `title LIKE '%%'` (source: `search_tracks`,
`Q_ITEMS`/`S_NAME` sort), i.e. every track in `title_sort` order. Live
probe (GETs only, 2026-11-20, server `pause`): `total 3265`, page 1 opens
`The A Team` (`title_sort` "A Team" — name-sorted), `offset=100` serves
distinct rows (`Avalon`), items carry `title_sort`/`rating`/`uri`.
Recorded in `OwntoneApi.tracks` doc + `docs/API.md` as a "do not
simplify" warning.

`Track` model gains `titleSort` (parses `title_sort`) + `sortTitle`
(fallback `title`) — same pattern as `Artist.nameSort` from #48.
`TrackRow.showAlbum` is additive: the default callers (Album → tracks,
Playlist → tracks) keep byte-identical secondary lines and semantics
labels; the label for Songs rows is `<title>, <artist> - <album>, M:SS,
N stars`.

Tests: **14 new cases** (R-15/R-12-cited, network-free, fake provider —
real `OwntoneApi` over `ScriptedAdapter`): home lists Songs; tap-through
renders two-line rows (`title` + `artist - album` + length); **play
accessory calls `playUris` with the track uri** (frozen repro — row tap →
`POST /api/queue/items/add?uris=library%3Atrack%3A5001&clear=true&

Songs section header = **A** (from `title_sort` "A List N", *not* the

## ASSUMPTIONS

* **Endpoint substitution is the faithful implementation of the frozen
  spec** — the spec names the intent ("paged list of every library track
  via the OwnTone JSON surface"); `/api/library/tracks` (collection) is
  impossible on this server (source + live 400). `type=tracks&query=` is
  the JSON equivalent per AGENTS §5 ("use the simpler JSON surface"), and
  the only candidate that returns *all* tracks with paging + stable
  name order. Documented in code + API.md with the do-not-revert warning.
* **Page size = the shared `PagedList` default (50)** — the adjudication
  pins "same paging/reconnect contract as the other browse screens"
  (every screen uses the default; the "100/page" in the run notes is
  superseded by the contract clause). Page-2-on-scroll verified either
  way (rows past 50 rendered).
* "Play accessory" for a track row = the row-tap play target (existing
  `TrackRow` behaviour — TrackRow carries no separate play icon by
  design, unlike collection rows; reuse-per-adjudication forbids adding
  one).
* Songs placed between Albums and Genres on the home (the R-21 drawer
  text lists "Playlists/Artists/Albums/Songs(+Genres)" — same order).
* Section header for Songs groups by `title_sort` (the served order),
  the #48 lesson re-verified live (page 1 opens "The A Team" under A).
* `/tmp` blocked for file tools → scratch in git-ignored
  `build/issue38/` (per-run instruction, #43/#40/#39/#48 precedent);
  the upstream `httpd_jsonapi.c` source copy also lives there (not
  redistributed — reference only, never a build input).
