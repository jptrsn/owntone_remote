## SUMMARY

R-25: `PagedBrowseList` gained an opt-in `groupKeyOf` parameter and renders
disabled alphabetical header rows (ReTune `basic_header` pattern,
`docs/retune-capture/10-genres/notes.md` — "ListView with alphabetical
section headers (disabled rows)") in the **loaded branch only** —
empty/error/skeleton are untouched. The header is emitted when an item's
normalized group key differs from the **previous loaded item's**, so
paging across a letter boundary emits it exactly once in either direction,
and `PagedList.reload` re-renders identically (the row list is recomputed
from the loaded items each build — there is no header state to duplicate).
`PagedBrowseScreen` forwards the parameter. **Enabled on Artists and
Genres only** (orchestrator adjudication: Songs belongs to #38,
Playlists/Albums stay off per spec).

Header row (frozen spec honoured): no ink, no tap callback, nothing
focusable; styled `textTheme.labelLarge` + `colorScheme.secondary`,
`EdgeInsets.symmetric(horizontal: 8, vertical: 8)` (8 px grid);
`Semantics(header: true, label: key)` wrapping `ExcludeSemantics(Text)` —
one node that is **structure, not a control** (no tap action, not
focusable) yet still carries the label for a11y readers (better than
ReTune's plain disabled TextView, per spec).

**Mandatory pre-step (live sort verification, done before hardcoding the
derivation — GETs only, 2026-11-20, server `state: pause`):**

* `GET /api/library/artists?cc=artist` (217 artists): the default order is
  **not** by display name — it is by the wire field `name_sort`
  (MusicBrainz-style: `Daniela Andrade` → `"Andrade, Daniela"` sorts under
  A; `Iggy Azalea` sorts under A too). Deriving the header from the
  **display name** produces **103 spurious group transitions** across the
  217 artists (A,D,A,T,A,I,B,C,B,T,…); deriving it from **`name_sort`**
  produces exactly **24 contiguous groups** (A…Y, each letter once,
  monotonic). `name_sort` is present on **all 217** artist objects.
* `order` param is **ignored** on this endpoint: `?order=asc`,
  `?order=desc`, `?order=name` all return the identical first five rows —
  the server's name_sort order is the only (stable) order, nothing to pin.
* `GET /api/library/genres` (79): also carries `name_sort`; default order
  is contiguous by it (18 groups A…V, e.g. `Big Band, Jazz` opens B after
  the A block). `cc=`/`offset`/`limit` do not reorder (the genres endpoint
  ignores paging, known since unit 005a).

→ Group-key derivation (frozen): `browseSectionKey(sortName)` where
`sortName = nameSort.isNotEmpty ? nameSort : name` (`nameSort` parsed from
`name_sort`, now on `Artist` and `Genre` models) — trim, uppercased first
character; anything not a letter (digits, symbols incl. `'N Sync`, empty)
folds to `#`.

Tests: **12 new cases** in `test/paged_browse_headers_test.dart`, all
citing R-25, network-free (scripted `FakeSource` fetch, no provider):
page `["Ann","Bob"]` → A and B each once; next page `["Cid"]` → B→C
transition exactly once; page continuing the open group → no duplicate
header (boundary in the other direction); `reload()` re-renders A/B/C once
each (no duplicates); digits/symbols/`#` collapse renders one `#`;
`groupKeyOf == null` → no headers (Playlists/Albums path unchanged);
empty state unchanged; header semantics = header flag + label kept, **no
tap action, not focusable**; tap on a header does nothing;
`browseSectionKey` unit cases incl. the live-verified
`"Andrade, Daniela"` → `A` pin (and the no-`name_sort` fallback to name).

## ASSUMPTIONS

* **"as the server sorts it" = `name_sort`** — the live check (above)
  forced this: the server orders by `name_sort` and display-name grouping
  is visibly broken. `name_sort` absent/empty (older servers, fixtures) →
  fall back to `name`.
* Non-ASCII letters keep their own uppercased group (`\p{L}` check) rather
  than folding to `#` — the spec names only digits/symbols for `#`; the
  server sorts accented names as their own contiguous run.
* "both directions" of the boundary rule read as: new page starts a new
  group (emit once) AND new page continues the open group (emit zero) —
  both have tests.
* Songs stays without the flag (#38 enables it there — orchestrator
  adjudication); Playlists/Albums off per spec.
* Header node design = `Semantics(header: true, label)` + `ExcludeSemantics`
  so "excluded from the semantics list … but still carry a label" is
  literally one heading node with no control actions; the frozen
  `Semantics(header: true)` requirement holds (the widget IS a `Semantics`
  with `header: true`).
* `/tmp` blocked for file tools → scratch in git-ignored `build/issue48/`
  (per-run instruction, #43/#40/#39 precedent).
