## SUMMARY

New `lib/src/ui/mini_player.dart` — the pinned bottom mini transport bar,
hosted as `Scaffold.bottomNavigationBar` (Scaffold's own layer: never
scrolls with the list, never overlaps row hit-tests) on three hosts:

- `BrowseScreenScaffold` → every browse screen (Library home, Search,
  Queue, all paged views incl. Songs/Artists/Albums/Playlists/Genres and
  the detail screens);
- the standalone `OutputsScreen` Scaffold;
- the standalone `SettingsScreen` Scaffold (idle-phase first launch has no
  current item → the bar collapses to nothing and the screen renders
  unchanged).

Behaviour (all per the frozen spec):

- **Two-line metadata** — `title` / `artist - album` (nulls/empties joined
  out), ellipsized, plus **prev / play-pause / next**.
- **Icon mapping identical to `mirror_handler.controlsFor`**: the widget
  literally calls `controlsFor(p)` and reads its first entry (the
  play/pause control) — playing → pause control, otherwise play. (Tests
  pin both directions; the icon is the *action*, ReTune-style.)
- **Presses route to `PlayerController` only** (`play`/`pause`/`next`/
  `previous`). **Never `QueueController.playUris`** — that add carries
  `clear=true` and replaces the queue (the issue-#21 lesson,
  `queue_controller.dart:172-174`). The routing tests capture calls on
  recording subclasses of both controllers and assert `playUrisCalls == 0`.
  Mutation-verified: rerouting the button to `playUris([])` reddens the
  routing tests.
- **Metadata-zone tap → `showNowPlaying`** (`root_screen.dart:19-20`,
  `popUntil(isFirst)`). Widget test: Library pushed under the NP root →
  tap → depth back to 1, exactly one NP route. On-device: Songs (two
  deep) → tap → lands on root NP.
- **Visible iff a current item exists** (playing or paused); hidden when
  stopped / `nowPlaying == null`. ReTune keeps dead transport buttons when
  stopped — **deliberately not copied** (the recorded simplification).
  Device-side the stopped state could not be observed without `PUT stop`
  (destroys the shared fixture) → `WITHHELD` with a fake-controller proof
  (see OBSERVED).
- **Tooltips + semantics labels on all three buttons** (ReTune's
  unlabeled ImageButtons not copied): `tooltip:` + `Icon(semanticLabel:)`
  — asserted via `find.byTooltip` + `getSemantics(...).label` in the
  a11y test and via uiautomator `content-desc` on-device
  (`Previous` / `Play` / `Next` / `Open now playing\n<title>\n<artist - album>`).
- **Offline → transport inert**: `onPressed` null on all three buttons
  while `conn.phase != connected` (widget test: null-`onPressed` × 3 +
  tap-does-nothing + `ConnectionBanner` coexists above the bar — different
  Scaffold layers).
- **No auto-hide** (persists by design — contrast `22-volume-toaster`).
- **Artwork thumbnail: icon-only v1.** The unit-010 `ArtworkProbe` cache
  only holds verdicts for URLs the mirror already probed; rendering a
  thumbnail would require an `Image.network` fetch beyond the probe cache
  → spec says skip. Zero extra fetches added.

Implementation traps walked into and out of (pinned in code comments +
tests):

1. **`MainAxisSize.max` Column = full-screen bar.** Scaffold lays out
   `bottomNavigationBar` with *loose* constraints; the metadata Column
   (default `mainAxisSize: max`) grew to the whole viewport — 800-px bar,
   zero-height body, list rows never built (observed as the
   body-not-rendering bug in this very session, mutation-verified:
   re-applying `max` reddens the new height assertion
   `the bar is a compact strip, not a full-screen layer`).
2. **Provider-less pumps.** `context.watch<PlayerController>` threw
   `ProviderNotFoundException` in ~89 existing tests that pump browse
   screens without the player providers. Fixed with the repo's own
   `rateTrack` precedent shape: `Provider.of<PlayerController?>(context,
   listen: true)` (nullable generic = null when unregistered) → collapse
   to `SizedBox.shrink()`. (`context.maybeWatch` does **not** exist in
   provider 6 — compile-checked.)

One existing test adjusted: `test/now_playing_screen_test.dart` "Go to
Album" asserted `find.descendant(of: albumRoute, text 'Test Track')`
findsOneWidget — the bar legitimately renders the loaded fixture's title
on the pushed screen too, so the assertion is now scoped to the
`ListView` (it asserts the album ROW, not the bar). No behaviour changed.

## ASSUMPTIONS

1. **Hidden-when-stopped key = `nowPlaying == null || player.isStopped`**
   — `PlayerController._refreshChain` already nulls `nowPlaying` on stop
   (both sides of the frozen "stopped/nowPlaying == null" phrasing agree;
   the belt-and-braces check costs nothing).
2. **Host set** = the three hosts the spec names (BrowseScreenScaffold +
   outputs + settings). That makes the bar present on Queue (via the
   scaffold) and on Search (via the scaffold) automatically; the Now
   Playing root and secondary screens (About, dialogs) have no bar.
3. **Metadata-zone tap stays live while offline** (navigation-only — same
   adjudication as the drawer's Now Playing entry); "offline inert" is
   read as the three transport buttons (the frozen repro: "offline →
   buttons disabled").
4. **`artist - album`** joins the two fields with `' - '` skipping
   null/empty; empty second line renders no row (ReTune's dead text row
   not replicated). Title falls back to `Unknown title` like
   `mediaItemFor`.
5. **Icon-only v1** (no thumbnail): rendering `artworkUrl` would add an
   `Image.network` fetch beyond the ArtworkProbe cache → spec's "costs no
   extra fetch" gate fails → skip.
6. **`bottomNavigationBar`** chosen over a Stack layer: it is Scaffold's
   own layer (never scrolls, never intercepts body hit-tests) and keeps
   the bar above the body but below drawers/snackbars for free.
7. The `now_playing_screen_test` "Go to Album" assertion was scoped to
   the `ListView` (see SUMMARY) — the bar legitimately re-renders the
   fixture title on the pushed screen; no product behaviour changed.
