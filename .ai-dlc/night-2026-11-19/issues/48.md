# Alphabetical section headers on Artists/Genres/Songs browse lists

(Canonical: https://github.com/jptrsn/owntone_remote/issues/48. Frozen copy for the 2026-11-19 overnight run.)


## Change
ReTune renders disabled alphabetical header rows inside its long browse
lists ("A", "B", … on Artists/Genres — `docs/retune-capture/03-artists/`,
`10-genres/`, layout `basic_header.xml`; search results already group in
our app). Our paged browse lists are plain `ListView.separated` with no
headers (`paged_browse_list.dart:115-132`) — a 1000+ artist list is
harder to scan without them. User decision 2026-11-19 (N-05).

## Expected
Header rows in `PagedBrowseList` (opt-in flag; enable for Artists,
Genres, and Songs when #38 lands — leave Playlists/Albums off for v1):
- Group key: first character of the item's primary name **as the server
  sorts it** — verify the sort is locale-stable via `cc=`/`order` params
  live before assuming; digits/symbols collapse to a `#` header.
- Header = non-clickable disabled row (ReTune semantics: header rows are
  disabled nodes), styled `theme.textTheme.labelLarge` + `colorScheme.
  secondary`, padding consistent with the 8px grid.
- Computed **client-side per loaded page** — the list is paged
  (`PagedList`, 100/page): the header appears when the group key changes
  from the previous loaded item, so paging across a letter boundary
  emits it exactly once (test both directions).
- Headers are **excluded from semantics lists** the way ReTune's are
  (they're structure, not controls) but still carry a semantics label
  for a11y readers (`Semantics(header: true)` — better than ReTune's
  plain disabled TextView).
- Empty/error/skeleton states unchanged (headers only in the loaded
  branch of `PagedBrowseList.build`).

## Where
`lib/src/ui/paged_browse_list.dart` (`groupKeyOf` parameter + header
rendering in the loaded branch), `paged_browse_screen.dart` (pass
through), `browse_screens.dart` (enable on Artists/Genres [+Songs per
#38]).

## Requirements
R-25. Diff-list N-05.

## Repro / verification
Widget test with the fake provider: pages ["Ann","Bob"] → headers A and
B each rendered once; second page ["Cid"] across a letter boundary adds
B→C transition exactly once; reconnection refetch (`PagedList.reload`)
re-renders headers identically (no duplicates); header rows not
focusable/not tappable. Gates green.
