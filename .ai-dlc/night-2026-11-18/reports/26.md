## SUMMARY

Elapsed/duration now share the playhead row in `lib/src/ui/now_playing_screen.dart`
(SCREENS.md item 7, R-03). The seek-bar was three stacked Column children —
`Text(elapsed)`, full-width `Slider`, `Text(total)` — so the times sat on their
own lines above/below a slider that stretched edge to edge, and a long title or
a 5-char duration displaced them. It is now ONE row:

```
Row( [Text elapsed] [Expanded(Slider)] [Text total] )
```

The slider is the Row's only flex child, so it receives exactly the leftover
space between the labels; the labels are non-flex (laid out first, at their
intrinsic width), `maxLines: 1`, `softWrap: false` — they can never be
squeezed, wrapped or ellipsized. Drag-state seek behaviour (spike Finding 14)
is unchanged (same `onChanged`/`onChangeEnd`, one `seek?position_ms=` on
release) — the seek tests still pass untouched, which is itself the
regression evidence for that contract.

New widget test (repo rule: derived from the requirement, R-ID cited):
`test/now_playing_screen_test.dart` → group
`playhead row — times share the slider row (issue #26, R-03)`: long 78-char
title + `10:30`/`45:12` durations at the 360×640 narrow surface, asserting the
elapsed Text, the Slider and the total Text render in ONE `Row`, the slider is
the row's only `Expanded` child (`flexed.single.child is Slider`, non-flex
children are exactly the two labels), the slider sits strictly between the
label rects, both labels share the slider's vertical centre (they are ON the
row, not near it), each label is one line and its laid-out width equals its
TextPainter intrinsic width (never squeezed), and no overflow.
Mutation-verified: reverting the Row to the old stacked layout (from
`git show HEAD~1:...`) makes the test FAIL; restoring it makes it PASS.

## ASSUMPTIONS

1. **Narrow width = 360 dp** (`wm density 480` on the pixel_7 image), not
   below: the app's documented viewport floor is 360 logical px (unit 004 —
   below it the app bar/entry row overflow for reasons predating and unrelated
   to this row; the widget test records the same). The defect itself is
   width-independent and is observed at both 411 dp and 360 dp.
2. **Pixel screenshot compare → render-tree geometry.** Screenshots were saved
   (`.night/pr26/…`, scratch, deleted before returning) but this model cannot
   read image input, so the comparison is the render-tree rect/child-structure
   evidence above (slider strictly between the labels, labels at intrinsic
   width, shared centre line, no overflow in the console) rather than a diff of
   pixels. The widget test carries the same assertions in CI.
3. **`10:00+` interpreted as 5-char `mm:ss` labels** (`10:30`, `45:12`). The
   app's existing `_fmt` is `DateFormat('mm:ss')`, which wraps hours (a
   123-minute track renders `03:45`), so a "3-digit minute" label cannot occur
   without changing the formatter — out of scope for a layout fix (issue #26
   names only the seek-bar layout). Recorded as an observation for a future
   pass; deliberately not widened here.
4. **Real-server long-title/10:00+ data via a local fixture**, not by mutating
   the shared server: the current item on 192.168.1.13 belongs to another
   session (item 208437, `01:29`); changing the queue/current item would be a
   shared-state mutation the hard rules forbid. So the real server supplied the
   connected-state observation (checks 5–8) and a loopback fixture
   (REST-only, cannot play audio) supplied the issue's long-title + 10:00+
   repro (check 9). The widget test pins the same case in CI.
5. Permission dialogs denied (`pm grant` afterwards to stop the churn); the
   notification/call features are irrelevant to this row.

## RESOLVED FINDINGS

- **Full-width slider + stacked times (the defect)** — fixed as described;
  pinned by the new mutation-verified test.
- **Long title must not displace the row** (issue's "may wrap/displace on long
  text"): observed on-device with a 78-char title — title stays 2-line
  ellipsized in its own slot, playhead row geometry unaffected (checks 9–11).
- **Label-squeeze**: structurally impossible now (labels are non-flex Row
  children); asserted both ways (test: intrinsic-width equality; device: 36 px
  labels at both 411 dp and 360 dp while the slider absorbed the whole width
  change).
- **Seek drag-state preserved**: the pre-existing drag-state seek tests
  (`one seek on release…`, `server update mid-drag…`) pass unchanged even
  though the slider is now narrower — they locate it via `find.byType(Slider)
  .first` and drag from its centre, so they exercise the new geometry.
- Tooling notes carried forward (no product impact): `flutter run`'s host VM
  port dies if `adb forward --remove-all` is run while it lives; and
  `evaluate_expression` needs the tool's DDS port (a raw `adb forward` to the
  device VM port gives "No compilation service available"). Serial discipline
  held: `emulator-5554` this run, verified by `ro.boot.qemu.avd_name` before
  every adb use, never by memory.
