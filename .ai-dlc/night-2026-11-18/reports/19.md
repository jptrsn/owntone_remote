## SUMMARY

The per-output volume slider on the Outputs screen is now rendered
**disabled but visible** for every output where `selected == false`, matching
the OwnTone web UI, and its enablement follows the live `outputs` websocket
update (the same screen re-gates in place — no relaunch, no re-navigation).

- `lib/src/ui/outputs_screen.dart` — the `Slider` in `_OutputRow` now gates
  `onChanged`/`onChangeEnd` on `enabled && output.selected` (was `enabled`
  alone, the connection phase). A Material `Slider` with a null `onChanged`
  is Flutter's canonical disabled-but-visible state: it keeps rendering
  (track, thumb, and the row's volume value stay visible) but attaches no
  drag recognizers, so a finger on it commits nothing. `output.selected` is
  read from the `OutputsController` slice, which refetches on every `outputs`
  (and `volume`) WS event (`outputs_controller.dart:_onWsEvents`, unit-012
  single-flight shape) — so a server-side selection change flips the slider
  in place through the existing rebuild path; no controller/model change was
  needed (`Output.selected` already carried the bit).
- The **checkbox stays enabled** for unselected outputs — selecting an output
  must remain possible; the issue (and the OwnTone web UI) gates only the
  volume control.
- `docs/REQUIREMENTS.md` — R-09 acceptance gained the bullet this fix
  implements ("volume control rendered disabled (but visible) for every
  output where `selected == false` … follows the live `outputs` websocket
  update"), cited by the widget test.
