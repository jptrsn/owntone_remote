## SUMMARY

The queue's "hide items played earlier" is now exactly the OwnTone web-UI
behaviour: a **pure visibility toggle** — with it on, every row before the
currently playing track is hidden; zero queue mutation of any kind (no API
call, no optimistic removal); a WS `queue`/`player` event that moves the
current track **re-anchors the cut**.

State of the code before this fix (verified): the option did **not exist** —
`git log --all -S "after playback" -- lib/` is empty and no remove-style call
existed in `OwntoneApi` (only `getQueue`/`clearQueue`/`playUris`). There was
therefore no mutation code to delete; the frozen spec's expected behaviour
was built as the pure filter, and the fix-unit note's zero-mutation evidence
requirement is honoured in full (request-log equality in tests + the device
request-capture below).

- `lib/src/queue/queue_controller.dart` — session-only `hidePlayedItems`
  on the controller (flipping it only notifies listeners) and the pure view
  model: `indexOfNowPlaying` (entry-id match, same contract as
  `findNowPlaying`, which now delegates to it) + `visibleQueue`
  (`sublist(index)` from the current entry; returns the SAME list when off,
  when the anchor is index 0, or when unanchorable — no current item or the
  current item not in the list, since hiding without an anchor hides
  arbitrary rows).
- `lib/src/ui/queue_screen.dart` — app-bar toggle (tooltip `Hide items
  played earlier` ↔ `Show items played earlier`, icon `visibility` ↔
  `visibility_off`) left of the clear icon; `_QueueList` renders a parent-
  computed `items` list instead of `controller.queue`, so the cut is
  recomputed from the CURRENT queue + `PlayerState.itemId` on every build —
  that recomputation IS the re-anchor (no stored index anywhere). The toggle
  stays pressable while offline (it touches nothing on the server).
- `docs/SCREENS.md` § Queue — app-bar row, a pure-filter paragraph, and an
  Actions row `| Hide toggle | none — pure view filter (issue #23) |`.

## ASSUMPTIONS

1. **"R-05 area" in the issue's fix-unit note → R-11 (Queue)** in
   `docs/REQUIREMENTS.md` (R-05 is Playback modes) — same misnumbering
   precedent as #19 (R-07→R-09) and #24 (R-08→R-13). Tests cite R-11.
2. **No prior mutation implementation existed** (git-history + API-surface
   check): the spec's "fix likely deletes mutation code" resolves to
   "builds the expected behaviour, which was missing". The zero-mutation
   evidence requirement is honoured regardless (request-log equality + the
   capture above).
3. **Session-only toggle state** (on `QueueController`, not persisted): the
   spec allowed "persisted-or-session, choose minimal"; session is the
   minimal choice — a viewing preference, no `SettingsStore` change. Losing
   it on app restart is acceptable; test 5 pins that it survives navigation.
4. **Unanchorable cut shows everything** (no current item, or current item
   not in the queue; and index 0 → full list): hiding without an anchor
   would hide arbitrary rows; pinned by test 4 + device check 9.
5. **XML pref-seed rejected by Android's parser** (`Missing attribute
   value` from `SharedPreferencesImpl` on a byte-standard
   `FlutterSharedPreferences.xml`, reproduced twice via `run-as`) — the
   app's own Settings UI was used to point at the fixture instead
   (deterministic; the app persists the same keys itself). Tooling note, no
   product impact.
6. **Toggle stays enabled while offline** — it mutates nothing server-side
   (that is the point of the fix), so there is nothing to disable it for;
   the clear icon's offline-disabling is untouched.
7. **Real-server cross-check is GET-only + toggle-only** — the live queue
   held the current item at index 0 (other session's state), where the hide
   cut is a documented no-op; the visible-cut behaviour is proven on the
   fixture (checks 6–9), the real-server row adds live-data zero-mutation +
   byte-identical-queue evidence without touching the shared queue.
