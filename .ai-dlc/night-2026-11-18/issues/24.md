# Issue #24 (frozen spec — source of truth for the overnight run; canonical: https://github.com/jptrsn/owntone_remote/issues/24)

Playing a search result should navigate to Now Playing, not stay on results

## Defect
From Search, tapping a result track starts playback but leaves the user staring at the search results.

## Expected
Tapping a search-result track that initiates playback must also **switch the active screen to the Now Playing view**, like every other play-from-listen path.

## Where
`lib/src/ui/search_screen.dart` play handler + `lib/src/ui/root_screen.dart` (the tab/nav switch mechanism — mirror how browse-screen taps navigate, if they do).

## Repro / verification
Disposable AVD + flutter-agent-lens: search → tap track → widget tree shows the now-playing screen (server stays paused; assert on navigation, not audio).
