# Issue #20 (frozen spec — source of truth for the overnight run; canonical: https://github.com/jptrsn/owntone_remote/issues/20)

Deselecting an output: no warning unless it's the only selected output (then stop playback)

## Defect
Deselecting an active output during playback always warns (the live-audio-redirect confirm in `outputs_screen.dart`), even when other outputs remain selected and audio continues uninterrupted.

## Expected
- Deselecting one of **several** selected outputs during playback: **no warning** — audio just continues on the remaining outputs.
- Deselecting the **only** selected output: warn; on confirm, deactivate it, and if the player is in `play` with zero selected outputs, **stop playback** (server-side `stop`, not just pause — nothing is playing anyway).

## Where
`lib/src/ui/outputs_screen.dart` (~line 69: the unconditional confirm), `lib/src/outputs/outputs_controller.dart`.

## Repro / verification
Disposable AVD + flutter-agent-lens. Server-side output selection on the shared server: Volumio Kitchen (AirPlay) and Server (ALSA) are the reliable outputs; Chromecast remote outputs fail server-side selection. **Supervised** for any state that could emit audio — anything that can start playback is `supervised: true` per AGENTS; otherwise run with the server verified paused.
