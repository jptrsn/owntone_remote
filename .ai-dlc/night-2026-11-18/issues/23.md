# Issue #23 (frozen spec — source of truth for the overnight run; canonical: https://github.com/jptrsn/owntone_remote/issues/23)

"Remove from queue after playback" should be a pure visibility toggle (hide items before current track)

## Defect
The "remove from queue after playback" option does not match the OwnTone UI/UX.

## Expected (match OwnTone web UI)
When viewing the queue, the user can **hide all items before the currently playing track**. It is purely a **visibility toggle** — no queue mutation of any kind (no API call, no optimistic removal).

## Where
`lib/src/ui/queue_screen.dart` (the menu/action implementing this), `lib/src/queue/queue_controller.dart` — the fix likely deletes mutation code and replaces it with a view-model filter + persisted (or session) toggle.

## Repro / verification
Disposable AVD + flutter-agent-lens: toggle on → rows before the current track disappear, `GET /api/queue` byte-identical before/after; toggle off → they reappear. New playing-track changes (websocket `queue` update) must re-anchor the cut.

## Fix-unit note
R-05 area. If a previous implementation issued real removals, the fix unit's evidence must show zero queue-mutating requests (logcat/http capture).
