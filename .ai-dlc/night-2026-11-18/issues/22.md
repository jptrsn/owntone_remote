# Issue #22 (frozen spec — source of truth for the overnight run; canonical: https://github.com/jptrsn/owntone_remote/issues/22)

Suppress the system volume panel on volume changes — app already renders the level

## Defect
Changing volume shows the **system volume UI** (Android's volume panel) even though the app already renders the server volume level (now-playing screen + rocker path). Redundant double indication.

## Expected
Rocker/server volume changes show only the app's own rendering; the system volume panel is not triggered. Rocker routing to the server must keep working (R-06, unit 003, backgrounded + foregrounded).

## Where
`lib/src/audio/mirror_handler.dart` (~lines 299–320 — the audio_service `onVolumeChanged` path; audio_service attaches a session `VolumeController` when volume callbacks are implemented, which is what makes the framework show the system panel).

## Repro / verification
Disposable AVD: press the volume rocker with the app foregrounded; screenshot/widget-tree must show no system volume panel, and the server volume (API) must still step by the configured rocker step. Real-hardware check on the Pixel 6 (THE test device) for the actual panel suppression — emulator volume keys are not equivalent.

## Fix-unit note
R-06/R-14 area; must not regress the backgrounded rocker behaviour proven in dv-004.
