# Issue #21 (frozen spec — source of truth for the overnight run; canonical: https://github.com/jptrsn/owntone_remote/issues/21)

Tapping a queued track clears the queue instead of advancing to it in place

## Defect
Tapping a queued track in the Queue screen currently **clears the queue** and plays only the selected track.

## Expected
Mirror OwnTone's web UI exactly: clicking a queued item **advances the queue in place** — the queue itself is unchanged, the selected item simply becomes the current track (queue-skip semantics), playback position moves to it.

## Where
`lib/src/ui/queue_screen.dart` tap handler, `lib/src/queue/queue_controller.dart` (~line 140 — the `POST /api/queue/items/add` + `playback=start` path is what replaces the queue).

## Repro / verification
Queue several items on the shared server (add **without** `playback=start` — safe while paused), then tap-through in the app on a disposable AVD and `GET /api/queue` before/after to prove the queue content is unchanged and `current_queue`/`item_id` moved. Reference behavior: OwnTone 29.3 web UI.

## Fix-unit note
R-05/queue area. The API surface for in-place queue advancement is documented in `docs/API.md` — read the endpoint before trusting a parameter name (AGENTS trap #3).
